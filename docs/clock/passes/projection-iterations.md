## Why this file exists

[The door's own rule](README.md) is *"the product it serves links it when the pass
is executed. A pass plan nobody links is provenance nobody can find."*

**That rule holds everywhere in this tree except here, and the reason is structural.**
Every other campaign on this shelf serves a **document** — a systems manifest — and a
document links its own provenance as a matter of course. This campaign serves an
**application**. A viewer's links are its user interface; a manifest's links are its
bibliography. `lace-projection.html` carries four `href`s and all four are runtime
navigation, which is what a viewer's links are for.

So these thirty plans had no document to link them, and **nothing did**: not the
door, not the product, not each other. Thirty `EXECUTED` pass plans, 1,898 lines,
unreachable from either entrance to this repository.

**This file is the missing document sibling**, in the shape this tree already uses
five times over — `quiet-door-N-ascii.md` on four shelves, `ascii-iterations.md` on
graphics. Measured at [iteration 4 pass 3](../../plans/verification-iter4-pass-3-findings.md).

## How to read the chain

Each pass writes a **title stamp** into the running viewer — `i1`, `i3p4`, `i5p6`,
`ixp1` — and the next pass cites that stamp on its `Evidence:` line. **Twenty-seven
distinct stamps over thirty files, no duplicates, and twenty-six of them are cited by
a sibling.** The chain was always intact; it was written in stamps rather than links,
which is why no checker could see it. The `Stamp` column below is the join.

The stamps are registered in [the namespace register](../../namespace-register.md),
where `i1`–`i3` collide with the graphics ASCII iterations.
