# Systems Manifest — HCC-A (Human Cognitive Compiler Architecture)

## Overview

HCC-A is Gear H: the enclosed driver that compiles Reality into local story, force, self, and behavior. It is not Lace Core. It is not Graphic D. Internals may add, merge, re-index, and delete **their own oil**. Those operations applied to the tape kill Rule Zero.

Source for this manifest: `docs/clock/philosophy-map.md` §1 (H1–H11), with housing/train from the same file’s Gear H and clock sections. Original philosophy attachment is not in git. Hands court remains `docs/graphics/` + `docs/systems-manifest.md`.

Loop as the source states it:

`R → I → RIC∥PFC → C → L → M → E → ISL → B → R'`

PFC at step n carries ISL from step n−1. Both RIC and PFC must turn. PFC-only is a locked train.

Stamps on every piece: `[H]` holder oil · `[X]` forbidden as Core mechanism · `[I]` kin-read only · `[GAP]` Hands silent.

This manifest does not close POINTER emission.

## Puzzle Pieces

### H1 — Reality (R)

- **Kind:** Region / constraint world
- **Source location:** philosophy-map §1 H1; loop start/end
- **Purpose:** Objective, constraint-bearing world. “Not directly accessible by any mind.”
- **Inputs:** Behavior B from a prior revolution (alters R).
- **Outputs:** Constraint on Interface I. Not a readable object inside a mind.
- **Preconditions:** There is a world that can constrain.
- **Effects:** Cup-impact / floor. New events become new structure for the next RIC.
- **Invariants:** R is not a mind’s ledger. R is not Graphic D.
- **Failure modes:** Treating R as a Lace store. Treating a chart as the strand.
- **Boundary & Coupling:** Entangled with I (signals) and B (feedback). Clean relative to Core: R is not an array. Non-obvious: “the cup hits the floor” is adjacent to R, not a WORD row.
- **Implementation implications:** Do not add an R table beside Graphic D.
- **Metaphor / diagnostic role:** Gravity on the cup; mainspring of the clock.
- **Key source language:** “not directly accessible by any mind.”
- **Hands:** adjacent. `[H]`

### H2 — Interface (I)

- **Kind:** Interface
- **Source location:** §1 H2
- **Purpose:** Body converts R into raw signals.
- **Inputs:** R (inaccessible as such).
- **Outputs:** Raw signals to RIC and PFC in parallel.
- **Preconditions:** A body / sensor path exists.
- **Effects:** None on the lace.
- **Invariants:** I does not compile. I does not store meaning.
- **Failure modes:** Calling I “ingest” for Contract II.
- **Boundary & Coupling:** Hands off both shafts. Entangled with whatever a holder actually senses. Off-shoe for Core.
- **Implementation implications:** Steward-adjacent only.
- **Metaphor / diagnostic role:** Case opening; skin of the gearbox.
- **Key source language:** Body converts R → raw signals.
- **Hands:** off-shoe. `[H]`

### H3 — RIC (Raw Input Channel)

- **Kind:** Mechanism / input shaft
- **Source location:** §1 H3; Gear H dual shaft
- **Purpose:** Preserve external structure: “X said Y”, timing, sequence, cause/effect traces.
- **Inputs:** Raw signals from I.
- **Outputs:** Structured arrival traces into Compiler C, in parallel with PFC.
- **Preconditions:** I is handing signals. PFC is also turning.
- **Effects:** None on Graphic D. Must not become a second log.
- **Invariants:** Order kept. Structure kept. Runs in parallel with PFC.
- **Failure modes:** RIC stored as a second punch-card beside the array. RIC silenced so PFC-only wins.
- **Boundary & Coupling:** Interface-coherence: RIC’s structured arrival is the only HCC output that matches Core Piece 3’s *kind* (order kept). It is still not Piece 3. Kin-read `[I]`, not implementation.
- **Implementation implications:** If someone “implements RIC” as a table, they built a second store.
- **Metaphor / diagnostic role:** Workpiece-facing shaft.
- **Key source language:** Preserve external structure. Runs **in parallel** with PFC.
- **Hands:** kin of arrival order if not stored twice. `[I]` / `[X]` if stored.

### H4 — PFC (Pre-Filter Channel)

- **Kind:** Mechanism / input shaft
- **Source location:** §1 H4; ISL feedback
- **Purpose:** Same signals through priors, templates, roles, threat models, ideology. Assigns interpretations *before* full compilation.
- **Inputs:** Raw signals from I. Priors from ISL_{n−1}.
- **Outputs:** Pre-interpreted stream into C, in parallel with RIC.
- **Preconditions:** An identity/prior pack exists or is empty. Empty is still a shaft, not an absence of the shaft.
- **Effects:** Can starve RIC if it wins arbitration.
- **Invariants:** Must turn with RIC. PFC is the previous identity installed as a pre-filter.
- **Failure modes:** PFC as Contract II ingest = Xiao intern + meaning table before append. `[X]`
- **Boundary & Coupling:** Tight loop with ISL. High dependency on H9. Conflict as Core ingest.
- **Implementation implications:** Adjacent as diagnosis of why a steward misreads Graphic D. Not a row type.
- **Metaphor / diagnostic role:** Prior-loaded shaft.
- **Key source language:** Assigns interpretations *before* full compilation.
- **Hands:** conflict if ingest. `[X]` / `[H]` as diagnosis.

## Decomposition Seams / Candidate Contract Boundaries (Ranked)

Author units H1–H11 do **not** separately own Core.

At gearbox granularity this resolves into **one sealed driver contract** (H) with internal fusion:

- Shared oil: L is the mutable store every internal piece reads/writes.
- Closed loop: ISL → PFC → C → L → ISL.
- Single legal external shaft: B.
- Single legal external intake kind: structure (RIC), never meaning.

Candidate cuts (ranked):

1. **H as one contract** (strong). Internals stay fused. This is the cut philosophy-map already chose.
2. **B as a dependent interface layer** over H (weak). B cannot function without the box. Low state coupling to Core, high dependency coupling on H.
3. **R as the world** (not a software contract).
4. **H11 YAML** as optional diagnostic wrapper over H (dependent layer).
5. **Do not cut** L, M, C from each other. That would invent wires the source treats as one mill.
6. **Do not cut** H into Graphic D. That is the rejected “cognitive compiler service inside the 1D array.”

Dependency coupling to Core is high (nothing to operate upon without the workpiece). State coupling to Core must stay **zero**.
