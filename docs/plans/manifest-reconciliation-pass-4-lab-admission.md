### Dependency rule

An open blocks the bounded Lab only when the experiment's validity changes if that open is held fixed to the specimen rather than globally resolved.

A candidate may pull a conditional open into scope. When it does, that candidate owns the added premise and must state it before admission.

## 2. SM-GAP-RM subquestions

SM-GAP-RM remains **one** open interface.

### RM-A — RETAIN?

Input:
- sampling-derived structural evidence.

Question:
- what source/ruling/derived condition warrants retaining structure as Lace?

Output, if answered:
- a retention decision or retained relation description precise enough to continue toward a legal append.

Must not be smuggled from:
- semantic/embedding similarity;
- adjacency;
- “every cell” default;
- future knowledge;
- oracle lookup;
- editor-chosen threshold not supported by the candidate's stated authority.

### RM-B — MATERIALIZE?

Input:
- a selected structure that may still exist only as an ephemeral sampling object.

Question:
- how is it grounded/resolved into one or more addressable 1D Lace operands?

Known machinery:
- L-M19 can ground a finite **already-selected/addressable** sample by repeated L-M05 Join.

Still open:
- how an ephemeral sampled structure crosses into that addressable domain when retention warrants it.

### RM-C — ROLE / ORDER?

Input:
- a candidate retained relation whose physical Join is ordered.

Question:
- where do the ordered operand roles come from, when the candidate requires such roles?

Rules:
- chronology alone is not a universal answer;
- D1's explanatory wording/ref_A/ref_B may be used to score a candidate but may not be secretly imported into a D1-blind candidate;
- RM-C may be candidate-specific rather than a universal one-rule-for-all-relations theorem.

### Partial coverage is legitimate

A candidate may cover:
- RM-A only;
- RM-B only;
- RM-A + RM-B;
- RM-A/B/C.

The Lab must report that coverage honestly rather than converting an incomplete candidate into a binary pass/fail for the whole GAP.

## 5. D1 oracle-independence classes

| Class | Allowed D1 use during derivation | Meaning of D1 score |
|---|---|---|
| **D1-BLIND** | no expected D1 pointer pairs | bounded independent evidence against D1 |
| **D1-SCHEMA-ONLY** | D2–D6 schema/storage constraints allowed; no D1 answer pairs | bounded independent evidence against D1 |
| **D1-WITNESSED** | specific D1 row already part of candidate's provenance | confirmation/witness only |
| **D1-DERIVED** | D1 answer pattern used to formulate candidate | consistency only; no independent validation |
| **ORACLE-CHEAT** | direct answer lookup/embed | adversarial-control result only |

Replay/prefix purity and oracle independence answer different questions.

A candidate can be perfectly replayable and still be oracle-derived.

## 6. Required scoring/accounting

A future retention run must publish at least:

```
candidate
authority
RM-A coverage
RM-B coverage
RM-C coverage
replay
oracle-independence
TP
FN
FP
pair/order mismatches
event/index mismatches
```

Definitions:
- **TP** — expected retained event produced at the correct bounded event with the correct ordered pair.
- **FN** — expected event missing.
- **FP** — extra retained event not in the oracle.
- **pair/order mismatch** — event exists but ordered operands disagree.
- **event/index mismatch** — candidate emits the relation at the wrong bounded step/index.

A candidate with TP=6 and FP>0 is not “6/6 perfect.”

## 10. Source-silence classes

- **SILENT-A:** source gives no RM-A retention predicate.
- **SILENT-B:** source gives a retention decision but no RM-B path to addressable Lace operands.
- **SILENT-C:** source gives relevant structural language but no executable/mechanical predicate.

Examples:
- “repetition strengthens stars” may support structure/accumulation yet still be SILENT-A.
- “a touch remains” strongly supports persistence/re-entry while remaining SILENT-A for general sampled retention.

Silence is a finding, not permission to invent a threshold.
