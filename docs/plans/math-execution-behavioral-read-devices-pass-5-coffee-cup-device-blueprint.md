# 1. Source obligations preserved

The direct source defines five causal positions:

\[
\mathsf{Conditions}
\to
\mathsf{Release}
\to
\mathsf{Trajectory}
\to
\mathsf{Impact}
\to
\mathsf{Aftermath}
\to
\text{future Conditions}.
\]

It requires the observer to preserve their distinctions.

### Conditions

Everything required for a fall/event may already exist without having caused it yet.

\[
\text{possible}\neq\text{fated}.
\]

### Release

The initiating boundary.

\[
\text{initiation}\neq\text{total causality}.
\]

### Trajectory / Control Window

After initiation and before Impact:
- time matters;
- interventions go from easy to speed-sensitive to partial mitigation to impossible;
- options narrow under uncertainty.

The question is:

> When could this outcome still be altered?

### Impact

Reality supplies the completed outcome.

\[
\text{actual result}\neq\text{complete causal explanation}.
\]

### Aftermath

Physics may be finished but causality continues:
- stories form;
- Meaning is assigned;
- Identity adjusts;
- reusable scripts form;
- future thresholds/conditions change.

Aftermath is causal, not commentary.

### Planning/literacy

The source requires holding all five positions rather than choosing one moment and calling it causality.

These are **BEH-REQ**.

# 2. Not a one-hot stage machine

A lawful Coffee Cup device does not reduce an event to:

\[
stage_t\in\{C,R,T,I,A\}.
\]

Instead define the simultaneous causal tableau:

\[
\mathcal T_C(E)
=
(C_E,R_E,T_E,I_E,A_E),
\]

where every component is available for the same event \(E\).

A component may be:
- supported;
- partial;
- unresolved;
- not-yet-occurred in live analysis.

Thus:

\[
\boxed{
\text{Cup literacy}=\text{simultaneous five-role availability}.
}
\]

The machine may highlight the currently actionable role, but does not erase the other four.

# 3. Coffee Cup device type

Define:

\[
\mathcal D_C
=
(Q_C,G_C,\Omega_C,\Delta_C,\omega_C;\Theta_C).
\]

## 3.1 Local state

A minimal descriptive device may use:

\[
Q_C
=
H_C
\times
F_C,
\]

where:
- \(H_C\) is holder-local aftermath/future-threshold state when the device is used recurrently;
- \(F_C\) is optional currently selected event-frame/boundary context.

For a pure one-shot description:

\[
\Delta_C(q,o,g)=(q,y)
\]

is lawful.

No stage state must be stored.

## 3.2 External/context domain

\[
G_C
=
T_{now}
\times
B_E
\times
A_{now}
\times
K_{phys}
\times
K_{social}
\times
M_{CF},
\]

where, when available:
- \(T_{now}\): current/event time information;
- \(B_E\): event boundary/frame being analyzed;
- \(A_{now}\): currently available intervention affordances;
- \(K_{phys}\): physical constraints;
- \(K_{social}\): social/interface constraints;
- \(M_{CF}\): explicit counterfactual/model assumptions.

Not every component is required for every descriptive query.

Crucially:

\[
T_{now}
\not\equiv
\text{Lace index distance}.
\]

# 6. Conditions

Define descriptive function:

\[
\mathsf{Conditions}_C(o,g)
\to
C_E.
\]

A Conditions claim says a feature:
- existed before Release;
- contributed to the possibility field;
- does not by that fact alone establish necessity or total cause.

Required fence:

\[
\boxed{
\mathsf{Condition}(x)
\not\Rightarrow
\mathsf{Caused}(x,E).
}
\]

No optimization machinery is required.

# 7. Release

Define:

\[
\mathsf{Release}_C(o,g)
\to
R_E.
\]

A Release claim identifies the initiation boundary:

\[
t_R.
\]

The source does not supply a universal detector for Release.

Thus exact event-boundary recognition is:

\[
[OPEN].
\]

In that case \(\Gamma\) / candidate preservation may be used.

It is not mandatory when Release is explicit.

# 8. Trajectory / control window

Define the live trajectory interval:

\[
t_R < t < t_I.
\]

The source gives an **ordinal narrowing**, not a numeric decay law.

A source-faithful device lift may represent the currently available intervention set:

\[
\mathcal A_C(t).
\]

The source pressure is:

\[
t_1<t_2<t_I
\Rightarrow
\mathcal A_C(t_2)
\preceq
\mathcal A_C(t_1),
\]

where \(\preceq\) means "no greater practical intervention freedom" under the declared model.

Do **not** assume literal set inclusion if the application admits qualitatively new but weaker interventions.

This is a DERIVED formalization of source narrowing.

### Source categories

The source describes an ordinal progression such as:
- easy/trivial intervention;
- speed-dependent intervention;
- partial mitigation;
- no remaining intervention.

Pass 5 does not assign numbers.

# 9. Counterfactual intervention analysis

Coffee Cup asks what could still be altered.

When the device evaluates a possible intervention \(a\), it must use S10's explicit counterfactual form:

\[
\mathsf{CFClaim}
=
(X,w_X,\mathcal A,\mathcal M,\varphi).
\]

Here:
- \(\mathcal A\) is the admitted intervention set;
- \(\mathcal M\) is the causal/model assumption set;
- \(\varphi\) is the claim about possible outcome change.

### Optional machine operators

A device may use:

\[
\Gamma:
X\to\mathcal P_f(\mathcal A)
\]

to generate candidate interventions.

It may use:

\[
\mathcal V(a,X)
\]

to test feasibility/constraint compatibility.

It may use \(\Psi,\tau,\rho\) for bounded counterfactual exploration.

But none is a source requirement for merely **seeing the window**.

The source does not define:
- utility;
- reward;
- loss;
- optimal intervention;
- global preference ordering over outcomes.

Therefore Pass 5 forbids an ungrounded:

\[
a^*
=
\arg\max_a U(a).
\]

If an application supplies an objective through \(G_C\) or \(\Theta_C\), then optimization may be performed under explicit external provenance:

\[
SEE\!-\!G
\quad\text{or}\quad
SEE\!-\!Q,
\]

not as a Coffee Cup source fact.

\[
\boxed{
\text{Cup causal literacy}\neq\text{optimization theorem}.
}
\]

# 11. Live-window stopping

For live intervention:

\[
\mathsf{LiveActAllowed}(t)
\]

requires:
- Release has occurred;
- Impact has not occurred;
- the declared intervention remains feasible.

Once Impact is observed:

\[
t\ge t_I
\Rightarrow
\mathsf{LiveActAllowed}(t)=\mathsf{false}.
\]

Thus any live intervention search must stop/refuse at C4.

This is not the same as stopping causal analysis.

Retrospective analysis of the prior Trajectory may continue after Impact, but it is counterfactual/history analysis and must remain stamped accordingly.

# 12. Impact

Define:

\[
\mathsf{Impact}_C(o,g)
\to
I_E.
\]

Impact claims identify:

\[
\text{what Reality produced}.
\]

A lawful Impact claim is backed by:
- Lace evidence if recorded;
- external evidence if not yet in Lace;
- or UNKNOWN if absent.

Impact constrains theory.

It does not identify:
- private intent;
- total cause;
- every missed intervention.

\[
\boxed{
Impact\neq CompleteExplanation.
}
\]

\mathsf{Aftermath}_C(o,q,g)

Aftermath may update holder-local:

- thresholds;
- expected interventions;

\[

\[
A_E
\to
H_C'

\text{future }C_{E'}.
\]

And, if behavior changes the world:

\[
A_E
\to
\text{later external event}
\to
\text{lawful future Lace arrival}.
\]

# 15. Research-operator disposition for Coffee Cup

| Operator | Cup status | Reason |
|---|---|---|
| \(\mathsf{Par}\) | OPTIONAL | simultaneous roles need coexistence, not physical/algorithmic parallelism |
| \(\Gamma\) | OPTIONAL | useful for ambiguous Release or intervention candidates |
| \(\mathcal V\) | OPTIONAL | feasibility/model checking |
| \(\Psi\) | OPTIONAL | only for explicit counterfactual search |
| \(\tau\) | CONDITIONAL | required for bounded inner search; live action also gates at Impact |
| \(\rho\) | OPTIONAL | may preserve several plausible causal/intervention candidates |

Kauffman branching and Xiao search are therefore **counterfactual machinery candidates**, not the Cup's causal ontology.

AgentScope's delayed resolution is useful when several causal hypotheses remain possible.

Petersen–Zech composition is useful for computing multiple role views, but not source-required as a neural realization.

Rowlands stop/control provides generic machinery precedent only.
