# Verification iteration 5, pass 3 — a token that changed underneath the tree

**Status:** `[PLAN]`. **Station:** maps. **Emission:** `[GAP]`. No `src/`.
**Iteration:** [iteration 5](verification-iteration-5-plan.md). **Prior:** [pass 2 findings](verification-iter5-pass-2-findings.md).

## 0. What probing settled before the plan was written

### `G2` looked like a collision and is not — the fifth time

The prefix-device campaign writes *"Point `G2` wherever a panel looks like a when and is not. Do not fill `G2`. `G2` stays `[GAP]`."* The register carries **Atomic gap `G1`–`G7`** on maps' shelf, a different station.

**Read at both ends**, `atomic-primitives-map.md:48` defines `G2` as *"Trigger, selection, arity, adjacency, and interleaving"* — **the pointer-emission gap.** The campaign means exactly that.

**Not a collision. A correct cross-shelf citation of a registered family**, by a campaign on `graphics` reaching accurately into maps' vocabulary. **The register worked, unprompted, and nobody had to be told.**

### The genuine finding is `Φ`, and it is not a collision either

**`Φ` has been tree-wide shorthand for the emission question**, written as `Φ = [GAP]` or `Φ [GAP]` in station notes, clipboards and campaign receipts for as long as those have existed. It names an open question.

**The prefix-device campaign has now given it a definition:**

> `docs/pointer-emission.md:36` — `## Φ — partial definition`
> `:45` — `Φ : L × R ↦ L 〈 (POINTER, r_1, …, r_k) 〉`
> `:7` — **Φ-morphism** is stated below. **Φ-schedule** is Q1.

**So the token changed kind.** It was a name for a hole; it is now a partially-defined object with one part **stated** and one part `[GAP]`.

**Both readings are defensible and that is the problem.** Every `Φ [GAP]` already written in the tree is still true *of the schedule* and **false of the morphism**, and nothing tells a reader which was meant — because when those notes were written there was only one Φ.

## 1. Why this is not pedantry

**The `src/` gate turns on emission being unanswered.** `docs/pointer-emission.md` is careful — it splits the two parts and says *"Not accepted"* ten times. **The rest of the tree is not**, because it wrote its notes before the split existed.

A reader — or an arriving agent under [the human's handover ruling](verification-iter5-pass-2-plan.md) — meeting `Φ = [GAP]` in a station note and `Φ — partial definition` in the law shelf has no way to tell whether the tree thinks emission is open or half-closed. **That is one inference away from the only prohibition this repository cannot afford to lose.**

**Nothing here proposes touching those notes.** Most are dated artefacts and [the standing rule](verification-iteration-1-plan.md) forbids rewriting them to look current. **The register is where a token's change of state belongs**, and the register does not carry `Φ` at all.

## 2. The thesis, stated so it can lose

**A token gained a definition, and every existing use of it became imprecise in the same commit — silently, because the register does not track what a token *is*, only who uses it.**

The register's 28 families answer *"whose token is this?"* It has no column for *"what kind of thing does this name — an open question, a defined object, a partial one?"* **`Φ` moved along that axis and no instrument in the tree could notice.**

**Falsifier:** if reading the tree's `Φ` uses shows they are all in dated artefacts or all unambiguous from context, then the ambiguity is theoretical, the register needs one row and nothing else, and §1's gate worry is overstated. **3b decides it by reading them, not counting them.**

**Second falsifier:** if the register turns out to have such a column already — or the rule covers this case — then the finding is that I did not read the register carefully enough, and it should be reported that way.
