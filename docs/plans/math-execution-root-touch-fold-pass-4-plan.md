## 4. Selection-placement problem

Pass 3 deliberately left sample/relation selection outside Join.

Pass 4 must determine where that responsibility belongs, or preserve it as [GAP].

### Candidate S-A - Core derives selection from \(L\) and current arrival

Shape:

\[
\mathrm{Select}(L,v)\rightarrow S.
\]

Advantages:
- no external side state;
- automatic punch-card behavior.

Required evidence:
- a source rule determining which relation/sample follows from \(L,v\).

Falsifier:
- if the rule would need meaning, similarity, learned state, document metadata, or an arbitrary heuristic, S-A fails.

### Candidate S-B - punch-card / Contract II carries explicit selection

Shape:

\[
\text{input}=(v,S)
\]

or equivalent relation assertion.

Advantages:
- Core remains mechanical.

Problem:
- current Contract II is raw word arrival / punch-card sequence with zero own store;
- no current source says relation operands arrive as a second channel.

Unless source evidence exists, do not invent this expanded input type.

### Candidate S-C - explicit operator/query/action chooses a sample

Shape:

\[
\mathsf{Ground}(S)
\]

is invoked only when a user/system operation explicitly selects existing Lace portions.

Advantages:
- explains arbitrary "any portion" capability cleanly.

Problem:
- the Hands graphics do not currently specify a general query/write operator beyond arrival/participation;
- adding one may exceed source authority.

Keep OPEN unless directly supported.

### Candidate S-D - selection is the current physical route/sample boundary

Shape:
- the route produced by arriving word sequence determines the currently grounded sample.

Potential support:
- Piece 8 sequence = physical route;
- Piece 9 dictionary definition route;
- Piece 10 document feed;
- C6 named relation families as views.

Problems:
- document/sentence boundaries are not row types;
- C6 family labels are views, not Core metadata;
- current source may not specify when a route sample begins/ends.

This candidate must be tested, not assumed.

### Candidate S-E - relation assertion itself *is* selection

Interpretation:
- Join does not "discover" a relation.
- When the system is given or forms a relation between two already-existing portions, the ordered operands of that relation are the selection.
- Core responsibility begins after selection.

This may turn selection into an interface precondition rather than another scheduler.

Pass 4 must test whether this is merely tautological wording or the cleanest authority-preserving boundary.
