## 5. Trace dispositions — evidence state, not authority

Pass 2 may use these **trace-disposition labels**.

They are not new repository authority classes.

### TRACE-COMPLETE

Every required edge for the claimed scope is pointable.

### SOURCE-ONLY

Mechanism is grounded in a source/clipboard but has no current Lab representation.

This is **not** falsification.

### NOT-YET-INSTRUMENTED

A lawful hypothesis exists, but current Lab instruments cannot express it.

### BLOCKED-ADAPTER

The first missing edge is a non-source/non-derived mapping between domains.

### BLOCKED-INPUT

The mechanism requires inputs unavailable from lawful Lace/Lab state.

### BLOCKED-OUTPUT

The source mechanism returns the wrong kind of object for the claimed Lace question.

### AUTHORITY-BLOCKED

The representation would require forbidden/external/semantic state.

### PREFIX-BLOCKED

The mechanism needs future/global information unavailable at the claimed prefix.

### FALSIFIED-BOUNDED

The candidate ran and failed a named bounded falsifier.

### SURVIVES-BOUNDED

The candidate survived the named experiment.

This does **not** mean accepted architecture.

### PLATFORM-UNESTABLISHED

The semantic/candidate claim is coherent at its scope, but claimed physical realization depends on a platform fact not yet evidenced.

### PLATFORM-REFUTED

A required physical capability is pointably unavailable in the target scope.

This rejects that **realization path**, not automatically the semantic mechanism.

## 6. Trace the five critical edge classes

### E1 — SOURCE → CLIPBOARD

Question:
- Is the mechanism pointably grounded in the source rather than reconstructed from memory?

Falsifier:
- current clipboard/mechanism claim has no exact source route or materially overstates the original.

Pass 2 does not reread every source.
Originals are reopened only when a candidate-bearing trace cannot be established from existing pointable provenance.

### E2 — CLIPBOARD → LAB REPRESENTATION

Question:
- Is the candidate representation faithful to the source mechanism?

Required distinction:

```
SOURCE MECHANISM
      !=
LAB REPRESENTATION / PROXY
```

Example already known:
- A5 supports repetition/strengthening;
- integer `WeightByRepetition` is a LAB-PROXY.

A faithful source-derived candidate and a proxy must never share an unqualified authority label.

### E3 — LAB REPRESENTATION → EXPERIMENT → RESULT

Question:
- Can the current Lab actually run/test the hypothesis it claims to assess?

For every executed candidate:
- exact command/procedure;
- exact fixture;
- expected result;
- actual result;
- falsifiers;
- replay/oracle-independence status where relevant.

For every unrun candidate:
- write `NOT-RUN`, not an inferred outcome.

### E4 — RESULT → LACE CONTRACT / OPEN

Question:
- What exact Lace question does this result bear on?

Allowed consumers include:
- `SM-C01 … SM-C21`;
- `SM-GAP-RM / RM-A / RM-B / RM-C`;
- `SM-X-*` integration boundary;
- explicit FORBID;
- **NONE**.

If consumer = NONE, the result may still be useful research evidence, but must not float as an architecture claim.

### E5 — LACE / SURVIVING CANDIDATE → PLATFORM REALITY

Question:
- Does this semantic/candidate result require a particular physical realization?

If **no**:
- record `NONE-AT-SEMANTIC-STAGE`.

If **yes**:
- name exact platform requirements;
- route each requirement to the platform/toolchain clipboard;
- distinguish:
  - source fact;
  - browser/device observation;
  - synthetic test;
  - NOT-RUN.

The direction is:

```
candidate semantic obligation
       ↓
required physical capability
       ↓
platform clipboard / observation
       ↓
feasible / unestablished / refuted realization
```

Never:

```
platform has API
       ↓
therefore Lace semantics
```

## 14. Falsifiers

### F1 — orphan source mechanism
A source mechanism is discussed as important but has neither a Lab path nor an explicit SOURCE-ONLY disposition.

### F2 — proxy laundering
A LAB-PROXY is described as though the source defined that representation.

### F3 — unrun result
A candidate is described as passing/failing without an actual run or pointable prior execution record.

### F4 — instrument mismatch
The instrument cannot represent the mechanism but the result is presented as a verdict on the source.

### F5 — orphan Lab result
A Lab result has no exact Lace contract/open/FORBID consumer and is nevertheless treated as architecture evidence.

### F6 — authority upgrade by score
A source/candidate becomes HUMAN/DERIVED/Core because it scored well.

### F7 — D1 overfit
D1 consistency is presented as mechanism identity or universal behavior.

### F8 — missing false positives
A candidate gets a “perfect” result while extra invented retention events are uncounted.

### F9 — adapter hidden
A cross-domain mapping is editor-created but stamped SOURCE/DERIVED.

### F10 — platform semantic leakage
A platform/API capability supplies the meaning of RM-A or any other missing Lace semantic rule.

### F11 — platform evidence laundering
Web documentation, synthetic host execution, browser observation, and Android/device observation are presented as equivalent evidence.

### F12 — hardware ignored
An implementation-relevant survivor has no named physical feasibility obligations.

### F13 — platform kills semantics
A failed realization path is reported as disproving the semantic candidate without justification.

### F14 — bounded result universalized
RM-B/RM-C or another bounded result is promoted outside its tested class.

### F15 — RM-A design begins
A new retention predicate/adaptor/threshold is proposed, selected, or ranked.

### F16 — implementation gate moves
Tracing machinery is treated as implementation permission.
